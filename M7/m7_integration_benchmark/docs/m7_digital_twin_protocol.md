# M7 Operational Synthetic-Twin Extension — Locked Protocol

## Status and terminology

This is an optional extension to the locked M7 integration benchmark. It does not
modify the baseline M7 generator, classifications, headline numbers, or figures.

The defensible name is **operational synthetic-aquifer twin**. It is not presented
as a field digital twin because it has no continuously connected physical aquifer
counterpart. The extension demonstrates the update–forecast–verify mechanism that
a field digital twin would require.

## Scientific question

> When a graph-constrained aquifer model is deliberately imperfect, do sparse,
> asynchronous observations improve future-state predictions and quantify
> predictive uncertainty relative to predeclared non-updating baselines?

This differs from locked M7, which tests whether age, topology, and chemistry
jointly reject false connections under known joint truth.

## State, forcing, and monitoring contract

- Twenty-four nodes use the fixed true-edge topology from the locked M7
  integration benchmark.
- Monthly hidden states are groundwater head, chloride, and dissolved silica.
- Exogenous drivers are recharge, pumping, and seasonal temperature.
- Twelve monitoring nodes are selected before simulation.
- Head is observed monthly; chloride and silica are sampled asynchronously every
  two and three months, respectively.
- Observation-error standard deviations are fixed before simulation.
- Forecasts are issued for 1-, 3-, and 6-month horizons.

These variables test complementary behaviour: head responds rapidly to recharge
and abstraction, chloride carries conservative dilution/concentration information,
and silica represents a reaction-sensitive hydrochemical state. This is a
state-space abstraction, not a substitute for MODFLOW or reactive transport.

## Sequential updating

The extension uses a perturbed-observation ensemble Kalman filter. Each cycle is:

1. propagate the previous posterior ensemble through the graph-constrained model;
2. compare available observations with the forecast observation ensemble;
3. update all connected states using forecast cross-covariance;
4. archive the posterior ensemble; and
5. issue forecasts before later observations are available.

Forecast evaluation is **prequential**. A forecast issued at time \(t\) may use
observations through \(t\), realized forcing through \(t\), the declared future
pumping schedule, and seasonal forcing climatology. It cannot use observations or
stochastic recharge anomalies after \(t\).

Raw ensemble spread is calibrated separately for each state variable and forecast
horizon using only monitoring residuals that have verified by the current issue
time. The multiplier is updated operationally as additional residuals become
available; future residuals are forbidden. Both raw and calibrated coverage are
exported. Because the time series are dependent, this is described as empirical
rolling split calibration—not as distribution-free conformal coverage.

## Anti-inverse-crime design

The hidden truth is not generated by the operational model. It differs through:

- an unmodelled preferential connection;
- heterogeneous node sensitivities;
- different retention and transport coefficients;
- nonlinear recharge response;
- stochastic recharge and process variability; and
- a local chemistry pulse absent from the forecast equations.

The operational twin is a simpler linear graph model. Consequently, successful
updating cannot be attributed to fitting data generated by an identical simulator.
This remains a finite structural-error experiment; it does not span all field-model
errors.

## Predeclared comparisons

1. **Updated twin:** nominal topology with sequential observations.
2. **Open loop:** identical model and prior, but no observations.
3. **Oracle persistence:** exact current synthetic state held constant. This is a
   deliberately strong and conservative short-horizon baseline.
4. **Oracle seasonal climatology:** month-of-year state mean estimated from the
   complete synthetic state only before the forecast-evaluation period. It is an
   intentionally strong known-truth benchmark, not an operational field baseline.
5. **Wrong-topology updated:** assimilates valid observations through a plausible
   but incorrect network.
6. **Shuffled-observation updated:** preserves observation distributions but assigns
   values to the wrong monitored nodes.
7. **Sensor-dropout updated:** randomly removes 50% of scheduled observations.

The controls separate the value of updating from the value of correct information
and defensible topology.

## Evaluation and uncertainty

Forecasts begin only after spin-up. Forecast origins occur every three months.
Metrics are calculated for all nodes, monitored nodes, and unmonitored nodes:

- RMSE, MAE, and bias;
- continuous ranked probability score;
- empirical coverage and width of nominal 90% prediction intervals; and
- raw (uncalibrated) coverage and the frozen spread-calibration multiplier;
- paired RMSE skill relative to each comparator.

Independent process/observation realisations—not forecast origins—are the
replication unit. Reported percentile intervals describe variation across those
realisations. Origins from one realisation are never treated as independent
replicates.

## Allowed claims

- The implemented system performs sequential state updating.
- Forecasts are evaluated on observations/states unavailable at issue time.
- Updating can be compared fairly with open-loop and information-quality controls.
- Known synthetic truth permits direct assessment of full-network prediction and
  predictive-interval calibration.

## Prohibited claims

- That the extension is a validated field digital twin.
- That it reproduces a named Ghanaian aquifer.
- That the graph-state surrogate has MODFLOW- or PHREEQC-level process fidelity.
- That forecast skill guarantees safe management decisions.
- That synthetic uncertainty calibration transfers unchanged to field data.

## Requirements for a field digital-twin claim

A future field extension must add a named aquifer and versioned conceptual model;
transient boundary conditions; MODFLOW-family flow simulation; transport/reactive
simulation appropriate to the stated claims; independently quality-controlled
monitoring streams; sequential parameter/state assimilation; prospective forecasts
registered before observations arrive; forcing-forecast uncertainty; model-structure
ensembles; data/version provenance; and decision-specific verification. Until those
requirements are met, “operational synthetic twin” is the scientifically accurate
term.
